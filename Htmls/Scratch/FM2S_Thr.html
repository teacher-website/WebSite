一、教材定位與技術原理

這是什麼

Facemesh2Scratch 是 Junya Ishihara（champierre）開發的開源 Scratch 3 擴充功能，使用 TensorFlow.js 的 facemesh 模型（源自 MediaPipe Face Mesh），只用一支網路攝影機就能在每張臉上取得 468 個關鍵點的座標。

  • 使用平台：stretch3.github.io，非 Scratch 官方網站。
  • 模型在瀏覽器本機執行，影像不會上傳伺服器。
  • 需要 WebGL：若學生電腦停用硬體加速會無法執行（見第八節）。
🔒 隱私提醒：臉部資料屬於生物特徵。雖然本擴充不上傳影像，仍建議課前依校內規定取得家長同意，並明確告知學生「不要錄影或截圖同學的臉」。

四、編號與座標原理

換算公式

模型在 640×480 的攝影機影像上取得像素座標，再換算為舞台座標：

x = 240 −（像素 x × 倍率）　鏡像開啟時
x = −(240 −（像素 x × 倍率))　一般開啟時
y = 180 −（像素 y × 倍率）

倍率 0.75 時，640×0.75＝480、480×0.75＝360，恰為舞台尺寸。本擴充不提供 z 座標，若要表現遠近，可用「兩眼距離」或「臉的寬度」當作替代指標 —— 這是很好的比例概念延伸。

務必先用「人數」守門

若指定的人不存在（例如畫面只有 1 人卻讀「第 2 人」），座標會是空白、甚至讓程式停住。標準寫法：

重複無限次
如果 (人數) > 0 那麼
定位到 x: 1人・2號 x y: 1人・2號 y

兩人對戰的專案則寫成「如果（人數）＞ 1 才讀第 2 人」。這是本單元最重要的程式習慣。

五、兩節課教學流程

第 1 節
0–10′
引起動機：示範手機的臉部貼圖或濾鏡，提問「電腦怎麼知道鼻子在哪裡？」引出 468 個關鍵點的概念，並說明這是「找特徵點」不是「認識你是誰」。
10–20′
環境設定：開 stretch3 → 添加擴展 → 允許攝影機 → 用「人數」積木驗證是否偵測成功。（此段最易卡關，預留緩衝時間。）
20–40′
完成範例 1：角色定位到鼻尖（第 2 號）。延伸讓學生改用眉心（169）做眼鏡、額頭（11）做帽子。
第 2 節
0–10′
複習編號：用學生版的「臉部點點小測驗」搶答，熟悉常用編號。
10–30′
完成範例 2 或 3：張嘴偵測（14 與 15）或眨眼偵測（160 與 146），帶入「兩點距離」與閾值調整的概念。
30–40′
分享與省思：作品展示，討論臉部辨識的應用與隱私界線（手機解鎖、監視器、濾鏡），完成 AI 倫理討論。

六、範例程式與學生易錯點

👃 範例 1：角色跟著鼻尖

當 🏳 被點擊
將攝影機的透明度設為 50
重複無限次
定位到 x: 1人・2號 x y: 1人・2號 y

易錯點：把編號填成 0（沒有第 0 號，最小是 1）；或忘記加「重複無限次」。

😮 範例 2：張嘴偵測

將 [嘴巴開合] 設為（14 號 y − 15 號 y）
如果 嘴巴開合 > 15 那麼 …

教學重點：閾值必須實測，並提醒臉離鏡頭遠近會改變數值。進階：除以「臉高度（11 號 y − 153 號 y）」做正規化，就不受遠近影響 —— 很好的比例教學素材。

😉 範例 3：眨眼偵測

如果 (160 號 y − 146 號 y) < 4 那麼 …

易錯點：沿用張嘴的閾值（15）導致永遠不成立。眼睛開合的數值遠小於嘴巴，約 3～6，需要學生自己觀察數值後決定。

👥 範例 4：多人應用

如果 (人數) > 1 那麼
角色 2 定位到 x: 2人・2號 x y: 2人・2號 y

提醒：人的編號會隨偵測順序改變，兩人交換位置時角色可能互換，這是模型限制，適合作為「AI 的不確定性」討論素材。

八、常見問題排除

完全沒有畫面，或擴充功能載入失敗
① 檢查攝影機權限是否被封鎖；② 其他 Chrome 擴充功能（廣告攔截、隱私保護）可能與之衝突，可用無痕／訪客模式開啟測試；③ 確認網路可連外以下載模型。
「人數」一直是 0
臉未被偵測。檢查：正面對鏡頭、光線充足不背光、瀏海或口罩是否遮擋、距離約 40～80 公分。模型剛載入的前幾秒屬正常延遲。
畫面嚴重延遲、瀏覽器變慢
468 點的臉部偵測運算量高於手部偵測。建議：關閉其他分頁與程式、避免多角色同時跑重複無限次、只偵測單人。若仍過慢，可改用 Handpose 或 PoseNet 的專案作為替代。
出現 WebGL 相關錯誤
Chrome 停用了硬體加速。至「設定 → 系統 → 使用硬體加速（可用時）」開啟後重新啟動瀏覽器；學校統一派送的原則檔若停用該項，需請資訊組協助。
選了「第 2 人」卻沒反應或程式停住
指定的人不存在時座標為空白，部分情況會中斷腳本。請務必先用「人數」判斷（見第四節）。
兩個人靠太近，角色會互換
人的編號依偵測順序給定，並非固定身分。請讓學生保持距離，或設計成「不在意誰是誰」的玩法。
作品在 Scratch 官網打不開
stretch3 的擴充積木非官方積木。請存成 .sb3 並以 stretch3 開啟；繳交作品時建議同時錄製操作影片。

九、評量指標與跨域延伸

📝 評量指標

  • 知識：能說出至少 5 個常用部位編號及其位置。
  • 理解：能說明為何要先用「人數」判斷再讀座標。
  • 技能：能自行實測並決定張嘴／眨眼的閾值。
  • 態度：能說明臉部資料的隱私風險與使用界線。

🔗 跨域連結

  • 數學：座標、差值、比例與正規化。
  • 健體：五官名稱與臉部肌肉表情。
  • 藝術：AR 濾鏡與臉部比例（三庭五眼）。
  • 資訊倫理：生物特徵辨識與個資保護。

🚀 延伸主題

  • 自製 AR 濾鏡（帽子、眼鏡、動物耳朵）。
  • 張嘴接蘋果、眨眼射擊等無接觸遊戲。
  • 臉部比例測量與美術課的三庭五眼對照。
  • 比較 Facemesh／Handpose／PoseNet 三者的適用情境。
