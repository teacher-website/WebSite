# 部落樂舞：火堆旁的節奏

> 建立日期：2026-09-23　·　對象：國小高年級　·　狀態：**範例 .sb3＋學生互動教學＋程式說明文件，已完成**
> 臺北市貓咪盃 **國小遊戲 AI 互動組**．情境選擇卡 遊戲組 玩法 1（部落樂舞・火堆旁的節奏）

## 一、這個專案是什麼

圍著火堆的部落樂舞場景，玩家用**頭部動作**演奏三種樂器，完成音樂精靈出的節奏：

| 動作 | 樂器 | 編號 |
|---|---|---|
| 向左轉頭 | 低音木鼓 | 1 |
| 點頭 | 竹鐘（高音） | 2 |
| 向右轉頭 | 沙鈴 | 3 |

每做對一個動作，**火堆竄高一截**並改變火光顏色；做錯時火光瞬間暗下來、扣一把火把。
第一關「節奏記憶」記住亂數產生的 3～5 個動作，第二關「節奏接龍」把節奏越接越長，接到 10 個就挑戰成功。

## 三、規格一覽

| 項目 | 內容 |
|---|---|
| 擴充功能 | Facemesh2Scratch（臉部 468 點，6 個積木，有「人數」守門積木）；攝影機需用**鏡像**模式 |
| 使用部位 | 鼻尖 (2)、臉部左緣 (455)、臉部右緣 (235)、額頭頂端 (11)、下巴 (153) |
| 動作判定 | 轉頭比 ＝（鼻尖x − 臉中心x）÷ 臉寬 × 100；點頭比 ＝（臉中心y − 鼻尖y）÷ 臉高 × 100；門檻 18／8（皆為變數）；`左右相反` 設 1 可把左右對調 |
| 避免重複判定 | 旗標變數「可以觸發」：預備姿勢（臉朝正前方）→ 1，送出動作 → 0 |
| 亂數節奏 | 第一關：清空後「重複（隨機取數 3 到 5）次：添加（隨機取數 1 到 3）」；第二關：只在末端添加一個 |
| 序列記錄 | 清單「節奏」（題目）與「玩家動作」（玩家），用「玩家第幾個」逐項比對 |
| 關卡通過 | 第一關 連續 3 輪完全正確；第二關 序列接到 10 個並答對 |
| 遊戲結束 | 火把 3 把，答錯扣 1 把，歸零結束 |
| 計分 | 每輪 10 × 動作數；連續 3 輪不出錯 → 火光全開，該輪 ×2 |
| 難度 | 提示間隔起始 0.9 秒，每答對一輪 −0.04 秒，下限 0.25 秒 |
| 角色 | 舞台、動作牌、木鼓、竹鐘、沙鈴、火堆、音樂精靈、火把、字卡（共 9 個） |
| 積木總數 | 580 |

## 四、驗證

以 scratch-vm 載入範例 .sb3，掛上模擬的 Facemesh2Scratch 臉部座標實際執行：

- **動作辨識**：預備／向左轉頭／向右轉頭／點頭／看不到臉 五種狀態全部正確；
  轉頭比 ±25、點頭比 21，臉寬 105、臉高 142.5（模擬臉）。
- **不重複判定**：頭一直向左轉 1.6 秒，只送出 **1 次**動作；把臉轉正後再轉一次才送出第 2 次。
- **全破路徑**：第一關 3 輪全對 → 第二關；序列 3→4→…→10，接到 10 個答對 → 通關 = 1，
  字卡「通關」、火堆「全開」、火把 3 把全亮，總分 1150。
- **失敗路徑**：連續答錯 3 輪 → 火把 3→0 → 遊戲結束，字卡「結束」、火堆「暗」、火把全滅。
- **計分**：連續第 3 輪起該輪 ×2（實測 10×4×2 ＝ 80 計入）。
- **難度**：提示間隔逐輪 −0.04，夾在 0.25 下限。
- **左右相反開關**：把 `左右相反` 設成 1 後，同樣的臉部資料由「左」變成「右」、由「右」變成「左」。
- **網頁**：Chromium 檢查，12 段積木圖全部正常渲染、四個實驗室無錯誤；
  試玩台自動玩 4 輪，第 3 輪火光全開 ×2、第 4 輪進入第二關，與 .sb3 規則一致。
- **尚未在實體攝影機上測試**：上課前請先在教室電腦試跑，並依畫面左上角的「轉頭比／點頭比」調整兩個門檻。

## 五、實作時修正的問題

0. **視訊左右相反（使用者實測回報）**
   攝影機積木原本設成不鏡像的模式，Facemesh2Scratch 的 `getX` 在
   `mirror === false` 時會回傳 `-1 × (240 − x × 倍率)`，
   也就是**臉部 x 座標整組變號**，轉頭比的正負跟著顛倒，向左轉頭會打到沙鈴。
   修正：攝影機改用**鏡像**模式（英文值 `on`；`on-flipped` 才是不鏡像），
   並新增變數 **`左右相反`**（預設 0，設成 1 會把轉頭比變號），
   現場若仍相反，改一個數字就好、不必動積木。舞台左上角也把這個變數顯示出來。


1. **每一輪的第 2 個動作永遠消失**
   原本寫成「廣播『打對了』並等待 → 再把『玩家答案』歸零」。
   動畫播放那 0.2 秒內玩家做的下一個動作會被寫進「玩家答案」，然後被那句歸零一起清掉。
   改成**先搬到「這次動作」並立刻歸零，再播動畫**。（教學網頁第 6 章有完整說明。）
2. **教學頁重畫時把標籤刪掉**
   `innerHTML` 重畫畫面會連同裡面的標籤元素一起刪除，之後再寫它就會丟例外，
   導致後面的實驗室全部沒有初始化。改成標籤與畫面分開兩個元素。

## 六、已知限制

- 門檻值受座位高度與攝影機角度影響很大，已做成變數並在教材中安排「先量自己的數字」的步驟。
- 臉部偵測比手部吃效能，建議關閉其他分頁；「辨識動作」已勾選「執行時不重新整理畫面」。
- 臉部資料屬於生物特徵：模型在本機執行、影像不上傳，但仍請依校內規定處理，不錄影、不截圖同學的臉。
- 作品無法上傳 Scratch 官網執行，請存成 .sb3 並用 stretch3 開啟。
