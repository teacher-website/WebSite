# Scratch 函式庫（基礎積木 × 自訂積木）

> 建立日期：2026-09-26　·　對象：國小高年級　·　狀態：**51 個函式、9 個 .sb3、7 個 .sprite3、教學網頁與網頁版，已完成並測試**
> 參考專案：`20260925_手勢辨識模組教學_Web`（版型、工具鏈）、`20260924_貓咪甜點店_片頭與選單_Web`（打字機、可跳過的等待、切換畫面）、
> `20260921_Scratch動畫製作教學_Web`、`20260915_Scratch積木教學_Web`（樣式、blk.js）
> 產生工具：`20260923_Scratch專案產生器`（sb3lib／svgkit／lint）、`20260924_SB3轉網頁工具`

把 Scratch 作品裡最常寫的技巧做成**自訂積木（函式）**：打字機、淡入淡出、抖動、清除分身、倒數計時、洗牌排序、重力跳躍……
只用 Scratch **內建積木**，不需要任何擴充功能（和 Handpose2Scratch／Facemesh2Scratch 系列無關）。

## 零、需求與決策紀錄（新對話接手請先看這裡）

**使用者的原始需求（2026-09-25）**
> 製作一個 Scratch 函式庫，裡面建置許多 Scratch 的技巧，都用函式來呼叫使用，像是動畫中的打字機效果、或者清空角色……
> 把可以模組化的功能建立成函式庫。不是 HandPose2Scratch、Facemesh2Scratch 那些，而是基礎的 Scratch 積木能用到的功能。
> 要 sb3 檔案及互動學習網頁，與之前方式一樣。

**使用者確認過的選擇**
| 問題 | 使用者的決定 |
|---|---|
| 範圍 | **8 類全做，約 40 個**（畫筆類不做）→ 實際 51 個（含輔助函式，例如「換到第 n 個造型」「更新計時」「無敵閃爍」） |
| 學生怎麼用 | **A＋B 混合**：動畫類做成可匯入的 .sprite3（角色自己用）；計算類放舞台，用廣播呼叫、結果寫進變數 |
| .sb3 分檔 | **每類一個＋完整函式庫** |
| 對象 | **國小高年級** |

**我（Claude）替使用者做的設計決定與理由**（使用者沒有反對，之後要改可以直接改）
- 「清空角色」解讀成兩個函式：**4-2 清除所有分身**、**4-3 清空舞台**（廣播「全部隱藏」＋「清除分身」）。標題、按鍵說明這類介面角色不接這兩個訊息。
- A 型函式內部只用「僅適用當前角色」的變數，整個角色可以匯出成 .sprite3。少數要跨角色的（字幕、跳過、生命值、目前說話者／台詞）是全域變數，
  **已實測**匯入 .sprite3 時 Scratch 會自動在舞台建立它們。
- B 型函式的「服務台」：`參數1～參數4` → `廣播（函式名稱）並等待` → 讀 `結果`（7-3 另有 `位置`）。舞台也可以直接呼叫。
- 清單不能當參數 → 清單函式都處理固定的清單「工作清單」。
- 動畫類用**計時器**算時間（不累加「等待」）；物理類（彈跳、重力、捲動、跟隨）用「一格一格」寫法。
- 「造型換成（數字）」的陷阱：3-6 播放造型改用 3-7「換到第 n 個造型」（重複「下一個造型」直到編號對，最多 50 次），lint 全部通過。
- 角色是原創的「圓圓」（橘色圓球）與「方方」（藍色方塊），沒有使用任何既有角色（包含 Scratch 小貓）。
- 教學網頁拆成**總覽頁＋8 個分類頁**（51 個函式放同一頁太長）；每類一個「試玩台」，所有試玩效果都照 .sb3 積木逐句翻成 JS。

**還沒做／可以延伸的方向**
- 在**真的 Scratch 編輯器**裡開啟檢查外觀（本機的沙盒連不到 stretch3.github.io）。`tools/check_stretch3.py` 已寫好，在有網路的電腦跑一次即可。
- 畫筆類（畫多邊形、畫圓、畫星星、蓋章軌跡）——使用者選擇先不做。
- 教師版說明（節數、分組）尚未製作。


## 四、踩過的坑（本專案新發現）

1. **headless scratch-vm 沒有畫面引擎時，「尺寸設為」完全沒作用**，而且角色移動不會「要求重畫」→「重複」迴圈在一個畫面內跑好幾百圈，
   一格一格的物理（彈跳、重力）會瞬間跑完。`test_library.js` 的 `fakeRender()` 補上這兩件事（看得見的角色有變化就 requestRedraw、尺寸夾在 5%～490%）。
   **之後其他專案測動畫或物理時也要用這一招**，不然會以為程式壞了（或以為它是好的）。
2. **按綠旗時計時器會歸零**：冷卻的「上次使用」、無敵的「無敵到」要在綠旗重設（−999、0），否則第一次會等很久。
3. **先把變數設好，再廣播**（產生器坑 2 的實例）：遊戲機制範例原本「收到開始遊戲才把生命值設成 3」，玩家的程式先跑、讀到上一局的 0，重來後立刻「遊戲結束」。測試抓到的。
4. **按鍵的程式還在跑時，再按同一個鍵不會重新開始**（`restartExistingThreads: false`）。冷卻範例原本用「說出…持續 0.4 秒」，連按被吃掉，改用「說出」。
5. **.sprite3 用到的全域變數**：匯入時 Scratch 會在舞台自動建立同名的全域變數，積木參照都接得上（`test_library.js` 的 `.sprite3 匯入` 驗證）。
6. **SB3轉網頁工具的清單監看**：清單包在有底色的數值框裡，清單長一點會出現一大塊深色底。本專案在 `make_play.py` 用 CSS 蓋掉；
   **建議之後修 `20260924_SB3轉網頁工具/template/player.css`**（`.mon-list` 那一段），修前先備份。
7. 角色不能整個移出舞台（Scratch 留 15 點在舞台上）：無限捲動用 ±250；滑入的起點會被擋在邊緣（看起來正好是「從邊緣滑進來」）。
8. Scratch 的「＝」遇到兩邊都像數字就比數值：補零的 `007 = 7` 成立（寫進 1-5 的說明與小測驗）。
