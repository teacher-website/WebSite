## 變更紀錄

### 2026-09-23（夜）　修正「揮手撈垃圾常常沒反應」（真正的主因）
- **重現方式**：改用「真人揮手的連續軌跡」而不是瞬間跳位來測試，結果如下。

  | 揮手方式 | 電腦實際看到的手勢 | 舊寫法 |
  |---|---|---|
  | 水平直線揮過去 | 預備 → 左 → 中間 → 右 | ✅ 撈得到 |
  | 揮到一半手自然往下掉 | 預備 → 左 → **預備** → 中間 → 右 | ❌ 撈不到 |
  | 揮成向上的弧形 | 預備 → 左 → **舉高** → 中間 → 右 | ❌ 撈不到，還多種一棵樹 |

- **原因**：① 看到「預備」就把 `揮動階段` 歸零；② 中途掃過「舉高」會觸發種樹並把 `可以觸發` 設為 0。
  真人揮手幾乎一定會發生其中一種，所以只有揮得非常標準時才撈得到。
  鍵盤 ← 直接廣播「撈垃圾」，跳過這段判斷，所以一直正常——這正是兩者結果不同的原因。
  （種樹上限從 5 放寬到 8 之後，弧形揮手誤種的樹會一直長出來，症狀才變明顯。）
- **修正**：
  1. 看到「預備」只把 `可以觸發` 設為 1，**不再把 `揮動階段` 歸零**。
  2. 新增變數 `揮動時間`：看到「左」時記下計時器，**超過 2 秒**沒揮到右邊才把這次揮動作廢。
  3. `揮動階段 = 1` 期間**不接受種樹與擋住**，弧形揮手不會被打斷、也不會誤種樹。
  4. 左右門檻 ±100 → **±80**，手不必伸到畫面最邊邊。
  5. 舞台新增 `可以觸發`、`揮動階段` 兩個監看視窗，卡在哪一步一眼就看得到。
- **驗證**：四種揮法（水平、下掉、弧形、慢揮）**全部都撈得到**，弧形那次遮蔭維持不變（沒有誤種樹）；
  「手一直舉著只種一棵樹」的規則仍然成立，三種結局重測正常。
- 教材：第 4 章新增〈揮手要撐得住〉整段（含上面那張對照表）、預備姿勢模擬器同步新規則、
  第 9 章疑難表改用監看視窗來判斷卡在哪一步。
- 舊版備份於 `_備份/*_20260923_1115.*`。

### 2026-09-23（傍晚）　修正「左→右撈不到垃圾」
- **問題**：使用者實測回報揮動撈垃圾沒有反應。以模擬手部資料重現後確認原因是
  **判斷順序**：原本的順序是「預備 → 舉高 → **張開** → 左 → 右」，
  而多數人揮手時手掌是張開的，於是揮到左邊、右邊都會先滿足「張開幅度 > 90」，
  一路被判成「張開」，`揮動階段` 永遠不會變成 1，撈垃圾自然不會觸發。
  （鍵盤 ← 可以撈得掉，證明舞台的處理程式沒有問題。）
- **修正**：判斷順序改成 **預備 → 舉高 → 左 → 右 → 張開 → 中間**，
  也就是「先看手在哪裡，手在正中間時才看手掌有沒有張開」。擋住廢水本來就是在鏡頭中間做，不受影響。
- **順帶修正**：「亂丟垃圾」原本寫成兩個「如果」，垃圾 3 會先變 5 再被第二個如果加成 6（一次加 3 件），
  改成「如果否則」。
- **新增回饋**：溪裡已經沒有垃圾時廣播 `沒垃圾了`，青蛙說「溪裡的垃圾都撈乾淨了，謝謝你！」——
  避免玩家分不清「動作沒被認出來」和「沒東西可以撈」。畫面下方的牌子在手到左邊時也改成顯示
  「手在左邊 → 再揮到右邊」。
- **教材**：第 3 章加入判斷順序的實測災情說明與一個自我驗證步驟（把手拖到最左邊、張開幅度拉到 180，
  結果必須還是「左」）；第 9 章新增〈遇到問題先看這裡〉對照表，並說明「先用鍵盤測一次」的除錯方法；
  動作判斷實驗室的判斷順序同步更新。
- **驗證**：張開手掌從左揮到右 → 三次都成功撈起（修正前 0 次）；六種手勢辨識、擋住廢水、三種結局全部重測通過。

### 2026-09-23（下午）　四項調整：種樹上限、位置公式、亂丟垃圾事件、隨機事件回合
- **種樹上限 5 → 8**，而且種滿之後會廣播 `樹滿了`，青蛙說「樹已經夠多了！看看溪裡還有沒有垃圾。」
  （原本種到第 5 棵以後按了沒反應，玩家會以為程式壞掉。）
- **樹的位置改用公式算**：分身依編號排列 `x ＝ 編號 × 52 − 236`、`y ＝ 編號 × 2 ＋ 6`，
  第 1 棵在 −184、第 8 棵在 180，剛好排滿岸上又不會蓋到水潭。改間距只要改一個數字。
- **新增第三個環境事件「有人亂丟垃圾」**：垃圾 +2（已有 5 件時只 +1，因為分身只有 6 個）、水質 −3，
  提示卡與青蛙台詞同步。這樣「垃圾、沒有樹蔭、偷倒廢水」三個問題在遊戲中都會動起來。
- **事件回合改成隨機**：開場時用自訂積木 `抽事件回合` 抽出兩個偷倒回合與一個亂丟垃圾回合，
  以「重複直到不一樣」確保三個回合不重複，每次玩的節奏都不同。
- 配合樹變多，回合結束的自然變化多一層：**遮蔭 ≥ 6 → 水質 +5**、4～5 → +3、＝3 → 0、≤2 → −5。
- 教學網頁：第 6 章改為「兩種事件」並新增亂丟垃圾與抽事件回合兩節、第 7 章新增小樹分身位置公式、
  第 5 章補上上限回饋的說明、第 9 章測試與可調數字更新；溪流模擬器新增「有人亂丟垃圾」按鈕。
- **驗證**（scratch-vm 實跑）：好 89／普通 57／壞 0、10 三種結局都到得了；
  8 棵樹位置正確且全部顯示；事件回合每次都不同且不重複；垃圾歸零時 6 個分身全部隱藏。
- 舊版備份於 `_備份/*_20260923_0245.*`。

### 2026-09-23　修正「最後一個垃圾撈不掉」
- **問題**：垃圾（與小樹）的本體在建立分身時，是直接用區域變數「編號」＋1 來數數；
  建立分身的那一瞬間本體的編號也變成 1～6，如果此時收到「重畫」，本體會判斷「編號 ≤ 垃圾」而顯示出來。
  本體的編號最後被設回 0，之後的「重畫」不再處理它，所以畫面上永遠留著一個撈不掉的寶特瓶。
- **修正**：本體改用另一個區域變數 **計數** 數數，**編號永遠保持 0**；分身產生後再把自己的「編號」設成「計數」。
  小樹角色也做同樣修正。
- **驗證**：垃圾歸零時 6 個分身與本體全部隱藏；小樹依遮蔭正確顯示；三種結局重新測試仍正常。
- 教學網頁第 7 章新增「本體 / 分身」兩段積木與這個坑的說明；程式說明文件的角色架構同步更新。
- 舊版備份於 `_備份/*_20260923_0114.*`。

## 一、這個專案是什麼

用**青蛙的視角**說故事：牠住的水潭一天比一天淺，同伴一隻隻不見了。
觀看者用 **Handpose2Scratch 手部動作**參與復育——撈起垃圾、種回溪邊的樹、張開手掌擋住偷倒的廢水。
做得好，水變清、動物回來；來不及擋住，水質就會惡化。共有 **好／普通／壞** 三種結局。

## 三、遊戲設計（修改時請保持一致）

| 項目 | 設定 |
|---|---|
| 三種生物 | 青蛙（主角）、翠鳥、水蠆（蜻蜓幼蟲） |
| 三種環境問題 | 垃圾淤積、溪邊樹木被砍（無遮蔭、水溫升高）、偷倒廢水 |
| 互動動作 | 手放低＝預備（y < −40）／手舉高＝種樹（y > 80）／左揮到右＝撈垃圾（x < −100 → x > 100）／張開手掌＝擋住（｜食指尖x − 小指尖x｜ > 90） |
| 避免重複判定 | 旗標變數「可以觸發」：看到預備設為 1，觸發動作後設為 0 |
| 變數 | 水質 0～100（起始 45）、垃圾 0～6（起始 5）、遮蔭 0～5（起始 1） |
| 行動效果 | 撈垃圾：垃圾 −1、水質 +5；種樹：遮蔭 +1；擋下偷倒：水質不變 |
| 惡化機制 | 沒擋到偷倒：水質 −20、垃圾 +1、水蠆消失；有人亂丟垃圾：垃圾 +2、水質 −3；回合結束：遮蔭 ≥6 → +5、4～5 → +3、=3 → 0、≤2 → −5；垃圾 ≥4 → 再 −3 |
| 流程 | 開場旁白 → 抽事件回合 → 4 個回合（各 12 秒；隨機 2 個回合第 5 秒偷倒、反應 4 秒；另 1 個回合亂丟垃圾）→ 結局 |
| 結局 | 水質 ≥ 70 且 垃圾 ≤ 2 → 好；水質 < 40 → 壞；其他 → 普通 |
| 分身 | 垃圾 6 個、小樹 8 個（位置 x ＝ 編號 × 52 − 236）；本體用區域變數「計數」產生分身，本體「編號」保持 0，分身產生後自己設定編號 |
| 畫面變化 | 水面 3 段造型與尺寸、水草 3 段、青蛙表情 3 段、小樹幼苗/大樹、垃圾分身數、水蠆與翠鳥出現條件 |
| 數學程度 | 只用加減、比大小、絕對值，沒有平方根或距離公式 |

## 四、驗證

以 scratch-vm 載入範例 .sb3，搭配模擬的 Handpose2Scratch 手部資料實際執行：

- 六種手勢狀態（看不到手、預備、舉高、左、右、張開、中間）辨識皆正確。
- **不重複判定**：手一直舉著 1.5 秒，遮蔭只 +1。
- **三種結局都跑得到**：什麼都不做 → 壞結局（水質 0）；只撈垃圾 → 普通結局（水質 57）；撈垃圾＋種樹＋擋下偷倒 → 好結局（水質 89）；只顧著種樹不理垃圾與偷倒 → 壞結局（水質 10）。
- **隨機事件回合**：多次執行抽到的回合皆不同，且兩個偷倒回合與亂丟垃圾回合不重複。
- **種樹上限**：連續種樹到遮蔭 ＝ 8 後停止，8 個分身位置正確（−184 ～ 180），再種會廣播「樹滿了」。
- 偷倒事件未擋下時，水質 −20、垃圾 +1、水蠆消失；水質回到 70 以上時水蠆與翠鳥重新出現。
- 網頁以 Chromium 檢查桌機與手機寬度：無水平捲動、無程式錯誤，四個互動實驗室運作正常。
- **尚未在實體攝影機上測試**：上課前請在教室電腦試跑一次，必要時調整三個門檻值（−40／80／90）。

## 五、已知限制

- 門檻值受攝影機高度與座位影響，教材第 2 章有「先測自己的座標」的步驟。
